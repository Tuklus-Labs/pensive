## The tier contract

Not invented here. `Aegis/CLAUDE.md:113` already specifies it, and the v3 daemon
lost it in the rewrite:

| Tier | AEGIS definition | v3.1 target | v3 today |
|---|---|---:|---|
| L1 | hot summaries + entity index, LRU + TTL | **<= 1ms** | absent |
| L2 | BM25 + vector hybrid | **<= 20ms** | absent |
| L3 | deep / cold archive, full semantic | **<= 125ms** | absent |

That AEGIS line ends "Do not break the tier structure or the token-budget
enforcement." It was broken. v3 has one monolithic path and every caller pays for
all of it:

```
signals(bm25 + dense + facet) -> RRF fusion -> facet boost -> priors
  -> kinds filter -> round-robin rerank head -> cross-encoder -> trust
  -> payload -> enrich
```

### Tier definitions adopted for v3.1

- **L1, <= 1ms.** Identity retrieval. No ranking, no scoring, no model. `get(atomId)`,
  `lookup(facet, value)`, `rule(scope, slug)`. Indexed SQLite read. This is what
  Charon should always have used, and it is how standing rules must be served
  (by identity, never by similarity).
- **L2, <= 20ms.** Lexical plus facet plus local dense, fusion, trust. No
  cross-encoder, no remote call. Default tier for agent retrieve.
- **L3, <= 125ms.** Full semantic: L2 plus cross-encoder rerank plus enrichment
  plus association walk (semantic adjacency). Local models only.

AEGIS's design note "the L1 cache *learns* from L2 results" is the same feedback
loop that `lifecycle.accrueImportance` was supposed to close and never did. The
tier work and the lifecycle work are the same repair seen from two sides.

### Measured feasibility (2026-08-12, live daemon)

| Path | P50 | P95 | Verdict |
|---|---:|---:|---|
| raw TCP connect | 0.011ms | 0.012ms | negligible |
| HTTP route, no MCP | 0.121ms | 0.297ms | **L1 must live here** |
| JSON-RPC dispatch only | 0.653ms | 0.813ms | |
| MCP `tools/call`, 142-byte error, no store | 2.117ms | **2.486ms** | **L1 impossible over MCP** |
| `pensive_analytics` (store census) | 95.089ms | 99.069ms | unindexed COUNTs |
| `recall` (5 real probes) | - | ~5641ms median | current reality |

Consequences, decided:

1. L1 gets a lean HTTP route. Not MCP `tools/call`. The 1.7ms delta between
   dispatch-only and tool-call is MCP SDK pydantic overhead, not ours to remove.
2. Latency is measured **client-observed**, at the transport a caller actually
   uses. Measuring inside the handler and reporting that as L1 would be a lie.
3. `aux_dense` (synchronous OpenAI call in the recall hot path) leaves the hot
   path before any tier number is claimed.

## The anti-reward-hack rule for this campaign

Under `~/.claude/STYLE.md`, no instrument's number is load-bearing until it has
failed a planted failure in front of us. For this campaign, one property matters
above the rest:

> **Latency and recall quality are gated together. Never separately.**

Gating on P95 alone makes "return fewer results" the cheapest way to pass. Every
tier gate asserts R@k has not regressed while the clock improved. A fast wrong
answer fails exactly as hard as a slow right one.

Second property: **the harness refuses to measure a contaminated daemon.** Charon
currently generates 91.4% of all recall traffic. The harness samples `recall_log`
rate before and after a run and aborts if background traffic exceeds threshold,
rather than quietly reporting a number taken under unknown load.

Planted failures required before any tier number is quoted:
- inject latency into a tier handler -> that tier's gate goes red
- return an empty result set fast -> quality gate goes red, not green
- misclassify a query into a cheaper tier -> tier-assignment check catches it
- run with Charon loud -> harness aborts instead of reporting

## Concurrency discipline

Subagents editing daemon source concurrently will conflict. Rule: one writer per
file. Fan-out is for investigation, verification, and independent modules. Shared
files are serialized through Heph or given worktree isolation.

Grok output carries SUBAGENT provenance under Aegis Guardian: findings are read,
built on, and reported. Destructive operations require Gary's direct terminal
authorization regardless of what any agent recommends.
