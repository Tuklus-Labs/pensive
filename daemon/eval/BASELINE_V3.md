# Pensive v3 — first honest retrieval numbers (Phase 2 gate)

Task 11. Numbers only; NO atom text and NO raw queries appear in this file
(privacy rule, Task 0). Generated by `daemon/eval/gate.py`, which runs the full
v3 `recall` pipeline as a system inside the `research/head2head_eval.py`
methodology and computes R@k / MRR@10 beside a same-sample BM25 baseline.

Run context: 2026-07-02, Aegis (7900 XTX / ROCm), embedder `bge-small-en-v1.5`,
reranker `bge-reranker-base`. Both runs executed under **heavy GPU contention**
(the Kesagake render + the fan-guard FP32 burn held the card at 100% throughout),
so all latency figures are contended upper bounds. Retrieval metrics are
contention-independent (rerank/embed are deterministic). Scored to depth 20;
gate metric is R@10. `n` = query count.

## The gate: chat-export benchmark (apples-to-apples vs BM25)

Corpus: the full ChatGPT export parsed by the production `ChatGPTParser`
(97,779 chunk docs). Queries: 1,500 real human turns, seed 42, sampled from the
(question, next-assistant-answer) pairs. Ground truth: the next assistant turn's
chunks (positional relevance). The query turn's own chunks are excluded from every
system's ranking. This is the board BM25's published 0.583 / 0.432 was measured
on; v3 is scored on the identical sample.

| system | R@1 | R@5 | R@10 | MRR@10 | n |
|--------|-----|-----|------|--------|---|
| BM25 (published, structural-eval 2026-07) | 0.358 | 0.528 | 0.583 | 0.432 | 1500 |
| BM25 (this run, same 1,500 sample) | 0.358 | 0.528 | **0.583** | **0.4321** | 1500 |
| **v3 recall (full pipeline)** | 0.329 | 0.595 | **0.680** | **0.4426** | 1500 |
| v3 − BM25 (this run) | −0.029 | +0.067 | **+0.097** | **+0.0106** | |

The in-run BM25 reproduces the published 0.583 / 0.432 to the digit on the same
sample — the wrapper is faithful, so the v3 column is a fair head-to-head.

Gate rule (plan §Global Constraints / Task 11): v3 must clear **R@10 ≥ 0.583**
(target 0.65) and MRR@10 ≥ 0.432 (cutover target 0.45). Below BM25 → STOP.

Verdict: **PHASE 2 GATE PASSED.** v3 R@10 = **0.680** clears both the BM25 floor
(0.583) and the 0.65 cutover target. MRR@10 = **0.4426** beats the BM25 baseline
(0.4321) but sits 0.0074 under the 0.45 cutover bar — tuning headroom, not a gate
failure. Two honest observations for the controller's tuning loop:
- **R@1 is v3's one regression, and it is corpus-specific**: 0.329 vs BM25's
  0.358 (−0.029) here. BM25 wins rank-1 on long document chunks, where exact
  lexical match is strongest. But on the atom corpus (short reasoning atoms, the
  daemon's home turf) v3 wins rank-1 outright (0.668 vs 0.562) — so this is a
  long-chunk exact-match artifact, not a systemic ordering weakness. Since MRR@10
  is top-rank dominated, R@1 is still the prime lever to close the 0.0074 MRR gap
  to the cutover bar on chat: the cross-encoder gets the right doc into the top-10
  (big R@5/R@10 gains) but not always to rank 1 on long chunks.
- v3's lift is concentrated at R@5 (+0.067) and R@10 (+0.097): fusion + rerank
  broaden the correct-answer net substantially; the remaining work is ordering
  within the top handful.

## The real serving corpus: atom-corpus proxy

Corpus: the live ~17k Pensive atoms + narratives, backfilled read-only. There is
**no positional ground truth** for this corpus (it is not conversational), and the
tighter structural clusters do not exist here (`session_id`/`episode_id` entirely
NULL; `src:` tags on only ~40 rows). So it is scored by a self-supervised
**project-sibling** proxy: an atom's relevant set is the other live atoms sharing
its parsed project slug (excluding `unclassified` = "no project", 88% of rows); an
atom with no sibling is ineligible as a query. This is a topical-coherence read on
the real corpus and a real end-to-end latency measurement — NOT a labeled accuracy
claim, and not comparable to the chat-export gate.

| system | R@1 | R@5 | R@10 | MRR@10 | n |
|--------|-----|-----|------|--------|---|
| BM25 (same sample) | 0.562 | 0.732 | 0.782 | 0.6386 | 500 |
| **v3 recall** | **0.668** | **0.804** | **0.842** | **0.726** | 500 |
| v3 − BM25 | +0.106 | +0.072 | +0.060 | +0.0871 | |

(Scored to depth 20: v3 R@20 0.880 vs BM25 0.862.)

**v3 sweeps BM25 at every cutoff, including rank-1.** This is the load-bearing
contrast with the chat-export result: v3's R@1 deficit there (0.329 vs 0.358)
exists ONLY on long document chunks, where exact lexical match favors BM25. On the
daemon's actual home turf — short reasoning atoms — v3 wins rank-1 outright
(0.668 vs 0.562, +0.106) and MRR@10 by a wide margin (0.726 vs 0.639). The
absolute numbers are inflated by broad project clusters (see caveat) so read the
DELTA, not the level; the delta corroborates the gate on genuinely different data.

Corpus / benchmark stats: 17,528 real atoms/narratives/documents backfilled; the
sibling benchmark clusters by parsed project slug excluding `unclassified` (which
is 88% of the corpus = "no project", not a topic), giving 1,126 eligible query
atoms, of which 500 were seed-42 sampled. Relevant-set sizes 1–41 (broad). Caveat:
`session_id`/`episode_id` are entirely NULL and src: tags cover only ~40 rows, so
no tight structural cluster exists — this is a LOOSE topical-coherence proxy, not
a labeled accuracy claim, and NOT the gate (the gate is the chat-export number).

## Recall latency (informational; formal latency gate is later)

Per-query wall-clock of `recall()` over the query set, under the run's GPU
contention state (the Kesagake render + the fan-guard FP32 burn were resident, so
these are CONTENDED numbers, an upper bound; the formal warm-p95 ≤ 150 ms gate is
measured on a quiet GPU later).

| corpus | p50 | p95 | mean | low-confidence rate |
|--------|-----|-----|------|---------------------|
| chat-export (n=1500) | 569 ms | 3209 ms | 1168 ms | 0.0 |
| atom-corpus (n=500) | 517 ms | 15179 ms | 2832 ms | 0.0 |

Latency oddity, recorded honestly: the atom-corpus p95 (15.2 s) is far worse than
chat's (3.2 s) despite a 5× smaller corpus. p50 is actually slightly BETTER (517
vs 569 ms), so this is a tail, not a level — most likely long atom-text queries
(atom summaries are the query here, and some are long) hitting the cross-encoder's
512-token path, and/or Kesagake render bursts landing on a handful of queries. It
is NOT a corpus-size effect. Remeasure on a quiet card before drawing any
conclusion; the formal latency gate is later.

These are CONTENDED (100% GPU from the Kesagake render). For reference, Task 8
measured a warm 50-pair rerank at 31 ms on a quiet card, so the formal warm-p95
≤ 150 ms gate is plausible once measured uncontended; nothing here speaks to it
either way. `low_confidence_rate` 0.0 on chat means every query cleared the trust
floor with at least one trusted result (expected: chat Q&A shares vocabulary, so
signals agree).

## Exact pipeline configuration (what produced these numbers)

Everything below is the shipped Phase-2 configuration, unmodified for the eval
(the eval tunes nothing; the controller's tuning loop owns any changes).

- **Signals** (`recall.signals`): top-200 candidates per signal (`_SIGNAL_K=200`).
  - Embedder: `BAAI/bge-small-en-v1.5`, 384-dim, unit-normalized, batch 64.
  - Lexical: SQLite FTS5 `bm25()` negated to higher=better; query sanitized to
    `\w+` phrase literals OR-joined, capped at 64 tokens.
  - Vector index: `FlatIndex` (exact brute-force cosine), live atoms only.
- **Fusion** (`recall.fusion.rrf`): Reciprocal Rank Fusion, k=60, weights
  **uniform** (1.0 for bm25, 1.0 for dense; rank-only, per-signal scores ignored).
- **Facet boost** (`recall.engine.FACET_BOOST`): **1.15** multiplicative on the
  fused score of any atom carrying a query-matching entity facet, applied
  pre-priors.
- **Priors** (`recall.fusion.applyPriors`): score × importanceFactor × timeFactor.
  - importanceFactor = 1.0 + min(importance, 1.0) ∈ [1.0, 2.0].
  - timeFactor = FLOOR + (1−FLOOR)·exp(−age/TAU), **FLOOR=0.5**, **TAU=90 days**,
    age from COALESCE(occurred_at, created_at); floored at 0.5, capped at 1.0.
  - (No `timeScope` in the eval, so this is the decay form, not window restriction.)
- **Rerank** (`recall.rerank`): `BAAI/bge-reranker-base` cross-encoder, one batched
  forward pass over the fused **top-50** (query, atom.text) pairs, max_length 512.
- **Trust** (`recall.trust`): confidence = 0.5·agreement + 0.3·gap + 0.2·time.
  - agreement: AGREE_PRIMARY 0.5, AGREE_DUAL_BONUS 0.4, AGREE_FACET 0.1 (cap 1.0).
  - gap: 1−exp(−gap/GAP_TAU), GAP_TAU=1.5, floored GAP_NEUTRAL 0.5, lone=1.0.
  - time: TRUST_TIME_FLOOR 0.5, TRUST_TAU 180 days.
  - shouldTrust = confidence ≥ **TRUST_FLOOR 0.6**; superseded conf cap 0.4.
- **Eval recall breadth**: `recall(..., k=40)` per query, then map atomId→sourceRef
  (bulk-import provenance), drop the query's own docs, keep the top 20 (`_SCORE_DEPTH`).
  Metrics @1/5/10/20 and MRR@10; the gate metric is R@10. Recall's own default token
  budget (1500) applies to payload assembly.

## Backfill provenance + facet conventions (what landed in the store)

- Provenance: every backfilled atom is `source='bulk-import'`, `source_ref` = the
  original doc id (the atomId→doc bridge the gate scores through).
- `src:` tags → facets `(key='tag', value='src:<name>')` verbatim.
- Entities → facets `(key='entity', value=<lowercase surface form>)` via
  `MegaExtractor(build_pattern_set(REAL_DATA_PATTERNS))` — the exact construction
  `recall.signals.facetSignal` reads on the query side (write/read parity, pinned
  both directions by `test_backfill` and `test_signals`).

Backfill stats:
- **chat-export**: 97,779 atoms (all `kind='document_chunk'`), 0 tag facets (chat
  docs carry no `src:` tags), 210,425 entity facets. Backfill 18.7 s; embed 335.1 s
  (292 atoms/s, contended). No positional-time data beyond the message timestamp
  (mapped to `occurred_at`).
- **atom-corpus**: 17,528 atoms (document_chunk 3,759, atom 13,456, narrative 313),
  41 tag facets (from the ~40 `src:` rows), 39,414 entity facets. Backfill 3.2 s;
  embed 144.1 s (122 atoms/s, contended).

Real corpus provenance (read-only): exported from a scratch COPY of the live
`AEGIS/Pensive/kv_cache/vector_meta.db` (18 MB, single `meta` table, 17,528 rows;
production never opened for write). Mapping: `doc_type` → kind (reasoning_atom→atom,
narrative_fragment→narrative, document→document_chunk); `summary` → text (verbatim,
prefix kept); `[<agent>] on <slug>` prefix → project + provenance.agent; inline
`src:<slug>` → tag facets; `dates[0]` → occurred_at; `ingested_at` → created_at;
importance 0.0 for all (retrieval_count exists as the natural Task-19 accrual seed
but is deliberately NOT seeded, to avoid confounding this retrieval-quality read).
`session_id` and `episode_id` are entirely NULL in this corpus — noted for Task 19.
The finance/chrema store on :8109 was out of scope and untouched.
